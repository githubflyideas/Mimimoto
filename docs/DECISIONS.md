# 立项决策记录 (ADR)

固化立项阶段已经定下的取舍。每条都标注了**为什么**，因为后来者最容易在不知道理由的情况下把红线拆掉。

---

## D-001 核心循环：一条语音，既是指令也是样本

家长发一条 10 秒语音（"今天讲三只小猪吧，小猪就叫小豆子"），系统同时把它当作：

1. 当日故事的**指令**（选题 + 定制参数）
2. 当日新鲜的**声纹样本**

孩子得到 15 分钟父母声音的故事。投入产出约 90 倍。

**为什么**：同类产品的首要死因是冷启动——家长录不完注册语料就流失。把采样变成日常行为的副产品，而不是前置任务。

---

## D-002 红线：绝不生成父母没说过的话

克隆声音只朗读**父母写的或从故事库选的**内容。AI 永不即兴生成"父母会说的话"，永不做孩子与合成父母的自由对话。

**为什么**，三条独立成立：

1. **法律** — 让真人说出他没说过的话，是所有深度合成法规的核心禁区。
2. **产品** — 孩子能随时和"爸爸"聊天，真实通话的价值被稀释；家长察觉后会反感。
3. **儿童心理** — 低龄儿童分不清合成与真人。没有数据支撑这是安全的。

实现层面：`pipeline` 只接受来自 `StorySource` 的文本，不接 LLM 自由生成通道。

---

## D-003 红线：永不采集儿童语音

孩子端不申请麦克风权限。

**为什么**：一次性绕开 COPPA 可验证家长同意、GDPR-K 年龄验证。同时是"不进 App Store Kids Category"的关键凭据——账号持有人、付费人、录音人全是成年人，孩子是被动收听者。

这条必须写进架构而不是隐私政策。

---

## D-004 红线：对端音频永不落盘

若将来做实时通话，只录本端原始麦克风，传输流与采样流完全分离。

**为什么**：只录自己全球基本安全。一旦落盘对端音频就变成通话录音——德国刑法 §201 将未经同意录制他人言语定为**刑事犯罪**（即使录音者是通话方之一）。目标市场中 DE / FR / IT / KR 全在雷区。

---

## D-005 声纹注册需活体挑战

注册必须：本人设备 + 当场朗读系统**随机生成**的短句。

**为什么**：既是合规要件（中国《互联网信息服务深度合成管理规定》要求编辑他人生物识别信息须取得单独同意），也让"上传别人的音频来克隆"在产品层面根本不存在。审核时这是最有力的材料。

顺带否掉了"从微信语音提取父母声音"这条路——那等于造一个任意人声克隆工具套亲情外壳，而当前 AI 拟声诈骗的头号场景恰恰是冒充家人索要汇款。

---

## D-006 降级阶梯，不做每日采样硬门禁

| 当天状态 | 孩子听到 |
|---|---|
| 有当日语音 | 父母的开场白 + 父母今天点的故事 |
| 无当日语音 | 库存声纹讲的预设故事，无开场白 |
| 连续多日无 | 同上，**不提示"爸爸没来"**，不制造遗弃感 |

**为什么**：声纹不会一天变，零样本克隆几秒参考音频就够——所以"必须采样才讲故事"不是技术约束，是 engagement gate。而它的代价是**家长忘了，惩罚落在孩子身上**：

1. 卸载不是因为产品不好，是因为它制造了一次家庭事故。
2. 目标人群（远洋、工地、倒班、大时差外派）本就无法保证每日窗口。
3. 家长一旦意识到"App 拿我孩子的失望逼我打卡"，信任归零。

激励靠**开场白的稀缺性**，不靠断供。另设库存池：出差前一次录 7 条排进队列。

见 `server/src/main/kotlin/mimimoto/schedule/`：`Tier` 与 `Plan`。

---

## D-007 送达时间锚定孩子本地时区

不是父母时区，不是服务器时区。DST 切换日是经典事故点，策略显式定义：

- 本地时刻**不存在**（春季跳变被跳过）→ 取时钟跃过该时刻的瞬间
- 本地时刻**出现两次**（秋季回拨）→ 取**较早**的一次

**为什么**：一旦占住"每晚 8:30"，它就是家庭仪式，别人极难替换——这是真资产。代价是送达失败变成高严重度事故。

见 `server/.../schedule/WallClock.kt`：`resolveWallClock`。

---

## D-008 永不空白

生成失败 → 静默回退到昨天的 / 库存故事。孩子的 20:30 不能空。

见 `schedule.Plan.fallbacks` 与 `Plan` 的构造：任何输入都产出可播放的计划，否则抛异常。

---

## D-009 分段生成，首段就绪即开播

15 分钟音频整段生成要几分钟到十几分钟，若整段生成完才发，就必须设"采样截止时间比送达早 2 小时"，体验很别扭。

改为按段落生成，只要生成速率 > 播放速率（1x realtime），后续段在播放过程中陆续补齐。首段延迟几十秒，截止时间的概念消失——父母 20:25 发语音、20:30 照常开讲。

代价：段间韵律连续性（同一 prompt audio + 上一段尾部做条件），以及段级失败回退。

见 `server/.../pipeline/Pipeline.kt`。

## D-010 TTS 选型：FireRedTTS3 ~~（已被 D-015 取代）~~

Apache-2.0，2026-08 发布。零样本克隆覆盖 24 语言 + 21 中文方言，目标语言全覆盖。

MiniMax-MLS-Test 上多语言平均说话人相似度 84.8%、平均 WER 3.754%，均为第一。

关键：**目标语言组合恰好是商业 API 的弱区**——ElevenLabs 泰语 WER 73.94 / 相似度 58.8，越南语 WER 73.42 / 相似度 36.9，日语 WER 10.65；FireRedTTS3 在泰/越两项均为最好。自建是质量优势而非仅是成本优势。

⚠️ **未决法务风险**：仓库协议是 Apache-2.0，但 model card 的 Usage Disclaimer 写明声音克隆功能"intended solely for academic research purposes"。两者互相矛盾。商用前必须取得作者书面许可或律师定性。**不要默认 Apache-2.0 就万事大吉。**

适配层 `server/.../tts/` 保持可替换，不把 FireRedTTS3 焊死。

**→ 这条已被 D-015 取代。保留原文是因为它记录了当时的权衡，而 D-015 推翻的正是其中一条假设。**

## D-011 录音端原生，播放端跨平台

形态定死在平板，操作系统不锁定（JP/KR/US 是 iPad，VN/TH/BR 是低价安卓平板）。

- **录音端 = 父母手机 → 必须原生**。iOS 的 `AVAudioSession` voiceChat 绕过语音处理、安卓的 `UNPROCESSED` audio source 与厂商 HAL 降噪，两套逻辑毫无共性，跨平台框架在这里只会两边都不对。
- **播放端 = 孩子平板 → 跨平台即可**。解码、排队、定时、断网缓存，跨平台框架胜任。

两条路径本来就该分开设计，正好也是原生/跨平台的分界线。

---

## D-012 一个 App，角色绑设备

父母手机和孩子平板装同一个 App，首次配置时钉死角色。退出孩子模式需 PIN，且入口不可见（长按 + PIN，不放按钮）。

**为什么**：拆两个 App 会制造"让对方去下另一个"的断点，杀掉一半激活。而五岁孩子会点遍屏幕上每一个像素——任何可见的"返回家长模式"按钮最终都会被点开。

孩子无登录凭据，仅作为 `ChildProfile` 数据对象存在。

---

## D-013 服务端用 Kotlin，录音端原生，worker 用 Python

服务端最初写成 Go，改为 Kotlin。理由按权重排：

1. **可招聘性**。这是商业产品，带小团队 + 外包分包。中日两地 Java/Kotlin 人才池比 Go 大一个量级。
2. **与安卓客户端共享模型代码**。客户端是平板，D-011 已定播放端跨平台。
3. **`java.time` 对这个问题原生更强**。`ZoneRules.getValidOffsets()` 返回 0/1/2 个 offset，正好是"缺口 / 正常 / 重复"三种情况。Go 版需要手写约 90 行推导候选偏移，Kotlin 版 12 行，且是标准库保证的语义而不是我们自己的推导。

放弃的 Go 优势是单静态二进制和更低的内存基线（JVM 约 200–500MB vs Go 约 20MB）。在按量付费的推理集群旁边这是真钱，但服务端大部分时间在等 GPU worker，不是瓶颈。

**运行时零依赖**是从 Go 版保留下来的约束，且在 JVM 上同样成立：`java.time`、`java.net.http`、`com.sun.net.httpserver` 全在 JDK 里；WAV 解码和 JSON 都是仓库内的实现（WAV 解码后来从 `javax.sound.sampled` 改为手写，正是为了让同一份 `core` 能在安卓上编译：门禁在手机和服务端必须给同一个答案），而不是一个要跟版本的依赖。测试用仓库内 runner 而非 JUnit，这样连不上 Maven 的构建主机也能跑全量测试（`scripts/build.sh`）。若 API 面扩大到这个交易不划算，换 kotlinx-serialization 是改一个包。

TTS worker 无论如何是 Python——模型是 PyTorch 的。这是个多语言系统，不存在"统一技术栈"的纯洁性收益。

**移植时做了一处交叉验证**：把 Go 版实测的三个频谱截止值（19969 / 8016 / 3492 Hz）钉进 Kotlin 测试断言。这在移植过程中抓到了一个真实缺陷——参考电平计算混用了原始谱和平滑谱，会让阈值偏移平滑量。这类静默数值漂移不会让任何测试变红，除非有人钉住具体数字。

## D-014 上行链路必须无损，下行用 Opus

**上行（家长录音 → 服务端）：WAV / FLAC，绝不用有损编码。**

Opus 在低码率下会主动限带（16kbps 落到 8kHz）。而 audioqc 判断一条录音能否用于克隆，
靠的正是频谱在哪里停止。如果客户端上传前先压一遍，门禁看到的是**编解码器的低通**而不是麦克风的——
真 48kHz 的干净录音会被判成「设备在上采样」，全军覆没。

同样的原因，安卓端必须用 `AudioRecord` 拿原始 PCM，不能用 `MediaRecorder`
（后者写出 AAC/AMR，每一种都限带）。浏览器端同理：不能用 `MediaRecorder`，
要用 AudioWorklet 抓 Float32 自己封 WAV。

这条极易被后人当作「优化流量」删掉，因为删掉之后**没有任何测试会变红**——
症状是通过率莫名下降，而且会被归咎于模型或阈值。

**下行（合成好的故事 → 孩子平板）：Opus，32–48kbps 单声道。** 免专利费，安卓原生支持，
对移工家庭的网络和流量友好。这一侧没有频谱分析，有损完全合适。

顺带：H.266/VVC 之类是**视频**编解码器，这个产品全程没有视频，与它无关。

## D-015 引擎换成 CosyVoice 2，首发语言收窄到中日英韩粤

D-010 选 FireRedTTS3 是看质量：它在目标语言组合上（尤其泰语、越南语）明显领先。
但它的许可是矛盾的——仓库写 Apache-2.0，model card 的 Usage Disclaimer 写声音克隆
"intended solely for academic research purposes"。商用产品不能带着这个上线。

调查后发现 **FireRed 是例外，不是常态**。同类模型大多真的可商用：

| 模型 | 协议 | 商用 | 零样本克隆 |
|---|---|---|---|
| **CosyVoice 2**（阿里通义） | Apache-2.0 | ✅ | ✅ 3 秒 |
| F5-TTS | MIT | ✅ | ✅ |
| VibeVoice-1.5B（微软） | MIT | ✅ | ✅ |
| Higgs Audio V2 | 开源 | ✅ | ✅ 5 秒 |
| Kokoro-82M | Apache-2.0 | ✅ | ❌ 固定音色 |
| Fish Speech | CC BY-NC-SA | ❌ | ✅ |

选 **CosyVoice 2**：Apache-2.0，克隆功能没有任何附加限制，中文是开源里最好的一档。

### 为什么不用商业 API

不是偏好，是算不过账。15 分钟中文故事约 3600 字；按 ElevenLabs 多语种
$0.10/1000 字符，**每晚 $0.36，每个孩子每月约 $11**。这类亲子订阅能收的价格大概
$5–10/月——毛利是负的。

自建：一张 L4/A10 对这类模型约 5–10 倍实时，1000 个家庭每晚 250 小时音频
≈ 25–50 GPU 小时，spot 价 $0.5/小时 → **每家每月 $0.4–0.75**。差一个数量级还多。

所以 GPU 调度、分段生成、跨时区填谷（D-009）不是性能优化，**是这个产品能不能成立的前提**。

### 代价：语言覆盖从 12 降到 5

CosyVoice 2 覆盖中（含方言）、粤、英、日、韩。原计划的泰、越、葡、西、法、德、土、意
**不在其中**。这不是技术细节，是产品事实：这些市场暂时做不了。

而这跟「首发市场收窄」那个未决项正好收敛——收窄到 **中日英韩**，顺带解掉许可问题。
移工输出国那条线（泰/越/葡/西）需要另找引擎或解决 FireRed 的许可，**等验证过孩子买不买账再说**。

### 实现层面：这次换引擎证明了适配层的价值

Kotlin 端几乎没动——它说的是我们自己的 worker 协议，引擎差异全在 worker 里面。
改的只有类名、`languages` 集合，和 `worker/server.py`。

顺带修正一处设计：语言集合原本是全局常量，现在挪到 `Synthesizer.languages`。
哪些语言存在是**当前加载的模型**的属性，全局列表会在换引擎时静默过期——这次就从 24 降到 5。

## 未决

- **声纹存储形态**。服务端集中存储是 GPU 调度的前提（父母手机不在线时任务仍要能排队），但等于持有高价值攻击目标——声纹泄露无法像密码一样重置。方向：服务端 + 每家独立密钥 + 原始录音短期留存后销毁 + 长期只留不可逆 embedding。**Phase 2 再做，在验证孩子是否买账之前属于过早优化。**
- ~~首发市场收窄~~ → **D-015 已部分决定**：引擎只支持中日英韩粤，移工输出国（VN/TH/PT/ES）暂时做不了。剩下的问题是在中日英韩里先打哪个。
- 已故父母声音的保存——产品一定会被这样使用。主动做还是明确禁止，出事之前定。
